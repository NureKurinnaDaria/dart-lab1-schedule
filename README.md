# Лабораторна робота 4. Розклад занять групи (варіант 4): модулі, файли, HTTP і сервіс

Це четверта версія консольної програми на Dart для розкладу занять групи
ПЗПІ-23-9. Модель з ЛР 1–3 (клас `Lesson`, запечатана ієрархія, сховища,
події) тепер оформлена як пакет канонічної структури, вміє зберігати розклад
у JSON-файл, читати його з CSV, отримувати державні свята із зовнішнього
сервісу й віддавати розклад власним HTTP-сервісом на `shelf`.

Усі лабораторні лежать в одному репозиторії як гілки:

- `lab1` — ЛР 1 (функції, замикання, колекції);
- `lab2` — ЛР 2 (класи, ієрархія, домішки, узагальнення, записи);
- `lab3` — ЛР 3 (асинхронність, потоки, ізоляти, тести);
- `lab4` — ця робота.

Гілку `lab4` створено від `lab3` командою `git switch -c lab4`, тож її історія
продовжує історію ЛР 3. Зміни ЛР 4 видно командою
`git diff lab3 lab4 --stat` і у веб-порівнянні GitHub (`compare/lab3...lab4`).
Гілки `lab1`, `lab2` і `lab3` між собою мають незалежні історії: ЛР 2 і ЛР 3 я
починала з копії попередньої роботи.

## Запуск

    dart pub get
    dart run bin/lab4_schedule.dart --help
    dart run bin/lab4_schedule.dart import example/lessons.csv
    dart run bin/lab4_schedule.dart report --top 2 --mask-teachers
    dart run bin/lab4_schedule.dart holidays --year 2026 --check
    dart run bin/lab4_server.dart
    dart test
    dart analyze
    dart format .
    dart compile exe bin/lab4_schedule.dart -o build/schedule.exe

Дані розкладу лежать у `data/schedule.json` (каталог `data/` у репозиторій не
потрапляє, його створює команда `import`). Сервіс слухає
`http://localhost:8080`; інший порт задається змінною середовища `PORT`.

## Що змінилося порівняно з ЛР 3

| Було в ЛР 3                           | Стало в ЛР 4                                                                       |
| ------------------------------------- | ---------------------------------------------------------------------------------- |
| Плоский `lib/`, демонстрації в `bin/` | Реалізація в `lib/src/`, фасад `lib/lab4_schedule.dart`, у `bin/` лише точки входу |
| Дані лише в пам'яті                   | JSON-файл (`LessonFileStorage`) і потокове читання CSV                             |
| Сценарій демонстрацій                 | Консольний застосунок на `args`: команди `import`, `report`, `holidays`            |
| Зовнішніх сервісів немає              | Клієнт державних свят Nager.Date з трьома рівнями відмов                           |
| Сервісу немає                         | HTTP-сервіс на `shelf` з маршрутами `/items`                                       |
| 15 тестів                             | 65 тестів                                                                          |
| Залежності лише `lints`, `test`       | Додано `path`, `args`, `http`, `shelf`, `shelf_router`                             |

## Структура програми

- `bin/lab4_schedule.dart` — точка входу консольного застосунку.
- `bin/lab4_server.dart` — точка входу HTTP-сервісу.
- `lib/lab4_schedule.dart` — фасад: `export` усього публічного API.
- `lib/src/lesson.dart` — модель `Lesson`, підтипи, домішки, `toJson` і
  `fromJson`, розбір і валідація рядків.
- `lib/src/lesson_storage.dart` — `LessonFileStorage`: збереження й
  завантаження розкладу в JSON.
- `lib/src/csv_reader.dart` — потокове читання CSV (`openRead`).
- `lib/src/holiday.dart`, `lib/src/holiday_client.dart` — модель свята й
  клієнт сервісу свят.
- `lib/src/cli.dart` — команди консольного застосунку.
- `lib/src/service.dart` — `ScheduleService`, маршрути, middleware журналювання.
- `lib/src/analysis.dart`, `report.dart`, `data.dart`, `async_repository.dart`,
  `schedule_events.dart`, `heavy.dart` — код з ЛР 1–3 без змін.
- `test/` — 11 файлів тестів.
- `example/` — приклад вхідного CSV і тіла запиту `POST`.
- `docs/` — звіт, вивід `dart analyze`, `dart test`, `dart pub deps` і
  `dart pub outdated`.

Уся логіка лежить у `lib/`, у `bin/` лише запуск. Тому тести підключають
`package:lab4_schedule/lab4_schedule.dart` і не залежать від точок входу.
Альтернатива, один файл у `bin/`, не дозволила б перевіряти логіку тестами.
Реалізація лежить у `lib/src/`, а назовні видно лише те, що перелічено у
фасаді: пакет можна переупорядкувати всередині, не ламаючи зовнішній код.

## Консольний застосунок

Розбір аргументів виконує `CommandRunner` із пакета `args`. Глобальні опції:
`--data-dir` (каталог з даними, за замовчуванням `data`) і `--file` (ім'я
файлу, `schedule.json`).

| Команда             | Опції                                                      |
| ------------------- | ---------------------------------------------------------- |
| `import <файл.csv>` | `-s, --separator` (роздільник полів, за замовчуванням `;`) |
| `report`            | `-t, --top`, `--descending`, `--mask-teachers`             |
| `holidays`          | `-y, --year`, `-c, --country`, `--check`                   |

`import` читає CSV потоком: `File.openRead()` → `utf8.decoder` →
`LineSplitter`, тож файл не завантажується в пам'ять цілком. Порожні рядки й
рядки з `#` пропускаються, некоректний рядок не зупиняє імпорт, а потрапляє у
`stderr` з номером рядка. `holidays --check` показує, скільки занять розкладу
припадає на день тижня свята (з урахуванням дати першого заняття).

Помилки виводяться в `stderr`, код завершення встановлюється через `exitCode`:

| Код | Значення                                                  |
| --- | --------------------------------------------------------- |
| 0   | успіх                                                     |
| 64  | некоректні аргументи                                      |
| 65  | некоректні або відсутні дані, відповідь сервісу не є JSON |
| 69  | сервіс свят недоступний                                   |
| 74  | помилка читання чи запису файлу                           |

## JSON

`Lesson.toJson` і `Lesson.fromJson` написано вручну, без кодогенерації. Поле
`type` зберігає тип заняття, а `fromJson` через `Lesson.create` будує потрібний
підтип. `LessonFileStorage` будує шлях через `p.join` з пакета `path`, а не
склеюванням рядків: розділювач шляху залежить від операційної системи.
`load` повертає порожній список, якщо файлу немає, а `save` створює каталог.

## Мережева взаємодія

`HolidayClient` отримує свята із сервісу Nager.Date
(`GET /api/v3/PublicHolidays/{рік}/{країна}`), який не потребує ключа.
Відмови трьох рівнів описано окремими типами винятків (`sealed class
HolidayException`):

| Рівень                    | Типовий виняток                                          | Поведінка                         |
| ------------------------- | -------------------------------------------------------- | --------------------------------- |
| Немає з'єднання, таймаут  | `SocketException`, `ClientException`, `TimeoutException` | `HolidayNetworkException`, код 69 |
| Статус відповіді не 2xx   | (статус перевіряється явно)                              | `HolidayStatusException`, код 69  |
| Некоректне тіло відповіді | `FormatException`                                        | `HolidayFormatException`, код 65  |

Статус 204 (даних немає) повертає порожній список. Тіло відповіді
декодується як UTF-8 вручну (`utf8.decode(response.bodyBytes)`), бо сервіс не
завжди вказує `charset`, і `response.body` тоді читав би кирилицю неправильно.
`http.Client` закривається у блоці `finally` (якщо його створив сам
`HolidayClient`).

## HTTP-сервіс

`ScheduleService` тримає розклад у пам'яті й після кожного додавання записує
його у файл через чергу (`_exclusive`), щоб паралельні запити не пошкодили
файл. Маршрути:

| Маршрут           | Відповіді                                                                                                                        |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `GET /items`      | 200, масив занять; фільтри `weekday` (1–7), `type`, `teacher` (підрядок без урахування регістру); 400 для некоректного `weekday` |
| `GET /items/<id>` | 200 або 404, якщо номера немає чи він не число                                                                                   |
| `POST /items`     | 201 і заголовок `Location`; 400 для некоректного тіла; 409, якщо таке заняття вже є                                              |

Ідентифікатор `id` у маршрутах це порядковий номер запису в сервісі. Власний
`Lesson.id` складається з кирилиці й пробілів і незручний в адресі, тому він
використовується лише для виявлення дублікатів (відповідь 409). Усі відповіді
мають `content-type: application/json; charset=utf-8`; невідомий маршрут теж
повертає JSON з кодом 404. Проміжний обробник `requestLogger` друкує метод,
адресу, статус і тривалість кожного запиту.

Приклади запитів і відповідей (`curl.exe -i …`) наведено у звіті.

## Тести

У `test/` 65 тестів (`dart test`: All tests passed). 15 тестів з ЛР 3 і нові:

- `lesson_json_test.dart` (4) — кругова серіалізація, невідомий тип, поле
  неправильного типу, відсутнє поле;
- `lesson_storage_test.dart` (4) — запис і читання, створення каталогу,
  відсутній файл, пошкоджений файл;
- `csv_reader_test.dart` (4) — коментарі й порожні рядки, некоректний рядок,
  великий файл (5000 рядків), відсутній файл;
- `cli_test.dart` (8) — довідка, невідома команда, `import` і `report`,
  пропущений рядок, відсутній файл, порожній розклад, `--top 0`, маскування;
- `holiday_client_test.dart` (10) — розбір відповіді й адреса, UTF-8, статус
  204, статуси 404 і 500, три різновиди некоректного тіла, відсутність
  з'єднання, таймаут;
- `cli_holidays_test.dart` (6) — команда `holidays`, коди завершення, `--check`;
- `service_test.dart` (14) — усі маршрути, фільтри, помилки, `content-type`,
  журналювання.

Мережу підмінено через `MockClient` з `package:http/testing.dart` (клієнт свят
і команда `holidays`); обробники сервісу перевіряються прямим викликом
`handler(Request(...))` без запуску сервера.

## Типи даних і приведення

- `late` і оператор `!` у значенні «non-null assertion» у коді не
  вживаються. Символ `!` трапляється лише як логічне заперечення.
- `dynamic` явно не пишеться, але його повертають `jsonDecode` і оператор `[]`
  класу `ArgResults`. Результат `jsonDecode` одразу присвоюється змінній типу
  `Object?` і перевіряється через `is`, а значення опцій `args` приводяться до
  потрібного типу.
- Приведення `as` є в `Lesson.fromJson` і `Holiday.fromJson` (значення
  `Map<String, Object?>` явно приводяться до `String` чи `int`; відсутнє або
  неправильне поле дає `TypeError`, який перетворюється на `FormatException`),
  у `cli.dart` (значення `ArgResults`) і в тестах (розбір JSON у відповідях).
  Метод `cast` у конвеєрі з ЛР 3 лишився після `where`, тож не може
  завершитися помилкою.
- Єдині виняткові коментарі `// ignore: public_member_api_docs` стоять над
  чотирма підтипами `Lecture`, `Practice`, `Lab` і `Consultation`. Первинний
  конструктор не має місця для власного `///`; його документація входить у
  коментар класу.

## Залежності

Прямих залежностей 7 (5 у `dependencies`, 2 у `dev_dependencies`), разом із
транзитивними 46 пакетів; повне дерево в `docs/deps.txt`.

| Пакет          | Навіщо                                           | Альтернатива, чому не вона                                                                            |
| -------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `args`         | команди й опції, довідка                         | ручний розбір `List<String>`: більше коду, немає автоматичної довідки                                 |
| `path`         | `p.join` для шляхів до файлів                    | склеювання рядків із `/` чи `\`: залежить від ОС                                                      |
| `http`         | запити до сервісу свят; `MockClient` для тестів  | `HttpClient` з `dart:io`: нижчий рівень, немає готової підміни для тестів                             |
| `shelf`        | HTTP-сервіс, `Request`, `Response`, `Middleware` | сирий `HttpServer`: немає проміжних обробників; `dart_frog` та подібні: важчі, чужа структура проєкту |
| `shelf_router` | маршрутизація `/items`, `/items/<id>`            | ручний розбір `request.url.pathSegments`: більше коду й помилок                                       |
| `test` (dev)   | модульні тести                                   | `assert`: немає звіту й очікування потоків                                                            |
| `lints` (dev)  | набір правил `dart analyze`                      | власний список правил: легко пропустити важливе                                                       |

`test` і `lints` у `dev_dependencies`, бо потрібні лише під час розробки:
пакет, що використовують інші, не тягне їх за собою.

`dart pub outdated` показав застарілими лише дві транзитивні dev-залежності:
`analyzer` (14.6.0 → 14.7.0) і `_fe_analyzer_shared` (110.0.0 → 111.0.0).
Їх оновлено командою `dart pub upgrade`: вони не потрапляють у залежності
виконання, нова версія сумісна з обмеженнями `pubspec.yaml`, а `dart analyze`
і `dart test` після оновлення проходять. Тепер `dart pub outdated` не знаходить
застарілих пакетів (`docs/outdated.txt`).

## Налаштування аналізу

`analysis_options.yaml` підключає `package:lints/recommended.yaml`, вмикає
`strict-casts`, `strict-inference` і `strict-raw-types` та додаткові правила
`prefer_single_quotes`, `always_declare_return_types`, `prefer_final_locals`,
`unawaited_futures` і `discarded_futures`. У ЛР 4 додано
`public_member_api_docs`: лінт знаходить публічні оголошення без `///`. Усе
публічне API має документаційні коментарі.

Результат: `dart analyze` без зауважень, `dart format` не змінює файлів,
`dart test` проходить. Повний вивід у `docs/analyze.txt` і `docs/test.txt`.

## Час запуску

`dart run bin/lab4_schedule.dart --help` тричі: 3198, 3086, 2958 мс (середнє
близько 3081 мс). Зкомпільований `build/schedule.exe --help`: 74, 50, 48 мс
(середнє близько 57 мс), приблизно в 54 рази швидше. `dart run` щоразу
готує код до виконання, а `dart compile exe` робить це один раз. Час залежить
від комп'ютера.

## Обмеження

- Сервіс не має `PUT` і `DELETE`; номери записів стабільні, бо записи лише
  додаються.
- Сервіс слухає лише `localhost` і не має автентифікації.
- `holidays --check` порівнює лише день тижня й дату першого заняття, кінець
  семестру не враховується.
- `import` замінює вміст файлу розкладу, а не доповнює його.
- Текст помилки некоректного JSON береться з винятку `dart:convert` і
  англійською.
- Реальна мережа перевірялась вручну; автоматичні тести використовують
  підмінений клієнт.
- Тривалість заняття, як і в ЛР 2, 90 хвилин.
